# P3 设计：知识融合（内部教材 + 外部 Web）

## 目标

给医疗助手加**第二路知识源**：内部 Qdrant 教材库是**稳定的基础知识**，但缺时效；
接 **Tavily Web 搜索**补**最新指南 / 教材外内容**，两路证据**融合重排**后统一作答。

## 为什么要「统一重排」而非「加权混合」

两路证据来源异构（教材段 vs 网页摘要），分数量纲不可比。与其手调「内部 0.6 + 外部 0.4」
这种拍脑袋权重，不如**把两路证据合并成一个池，用同一个 BGE reranker 在同一标尺上重新打分**，
让最相关的（不论来源）自然浮上来——**来源中立、无需调参**。

## 实现（`external.py` / `med_nodes.py: retrieve_external / fuse`）

```
plan → retrieve_internal ─┐
       retrieve_external ─┴─ fuse（合并 → 统一重排 top-k）→ answer
```

| 环节 | 实现 | 关键点 |
|------|------|--------|
| 外部检索 | `retrieve_external` 调 `web_search()`（Tavily） | 受 `use_external` 开关控制；网页正文截断 800 字 |
| 优雅降级 | `try/except` 包住 Tavily 调用 | 失败/未配密钥 → 返回空，**只用内部源继续**，不让整条链崩 |
| 融合 | `fuse` 合并 `internal + external` → `rerank` 取 `FUSE_TOP_K=6` | 对（指代消解后的）原问题重排 |
| 来源标注 | `内部·教材#{id}` / `外部·{title}（{url}）` | 作答时按来源区分，前端给「内部/外部」标签 |

## 关键设计取舍

- **联网是用户开关（`use_external`）**：默认关（快、省、够用），需要时序/最新指南再开——
  把"慢且可能引入噪声"的外部源交给用户按需启用。
- **外部正文截断 800 字**：网页内容常很长，过长既拖慢重排、对作答也无必要。
- **降级而非报错**：医疗答复的底线是内部教材这条稳路；外部源是"锦上添花"，挂了就退回内部，
  保证可用性。
- **融合接口在 [P1](P1_DESIGN.md) 就预留**：`fuse` 节点基线期只重排内部证据，本期把外部证据加进
  同一个池即可，下游 `answer` 不动。

## 验证

开启联网问「最新的高血压管理指南有什么变化」→ 内部教材给基础分级用药、外部 Web 补最新指南要点，
`fuse` 重排后两路证据混排，答案分别标注内部 `[1]`/外部 `[3]`，并在两路冲突时指出分歧。✓
关闭联网或 Tavily 失败 → 自动只用内部教材，链路不中断。✓

## 待办

- 外部源目前只有 Tavily；可加权威医学站点白名单 / 域名过滤提升外部证据质量。
- 内外部冲突目前靠 `answer` prompt 提示分歧；可加更显式的"可信度分层"（教材 > 权威指南 > 普通网页）。
