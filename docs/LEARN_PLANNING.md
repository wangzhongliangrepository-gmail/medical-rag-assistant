# 学习串讲：Planning（拆解问题）

> 医疗助手的 `plan` 节点：把复合问题拆成多方面子问题分别检索。配合 `med_nodes.py` 阅读。

## 一、这个节点干什么

代码（`med_nodes.py` 第 89-108 行）：

```python
_PLAN_PROMPT = """你是医疗问答规划器。把下面的问题拆成 1-3 个可独立检索的子问题，
覆盖问题的不同方面（如疾病机理、药物选择、副作用、用药注意事项等）。
若问题本身很单一，只输出一个子问题（即原问题）。
问题：{question}"""

class SubQuestions(BaseModel):
    questions: list[str]

def plan(state, config):
    question = state.get("standalone_question") or state["question"]
    structured = _llm(config).with_structured_output(SubQuestions, method="json_mode")
    result = structured.invoke([...])
    subs = result.questions or [question]
    return {"plan_questions": subs, "sub_questions": subs}
```

干的事：**让 LLM 把一个复合问题拆成 1-3 个能各自独立检索的子问题。**

## 二、实际拆解例子

**例 1：复合问题 → 拆成多方面**
```
输入："二甲双胍的副作用和禁忌症"
拆成：["二甲双胍的副作用", "二甲双胍的禁忌症"]
```

**例 2：多方面问题**
```
输入："高血压怎么治，平时生活要注意什么"
拆成：["高血压的一线治疗药物", "高血压患者的日常生活注意事项"]
```

**例 3：单一问题 → 不拆（关键）**
```
输入："二甲双胍的副作用有哪些"
拆成：["二甲双胍的副作用有哪些"]   ← 只有 1 个，等于没拆
```

**例 4：复杂多方面**
```
输入："糖尿病人能喝酒吗，对血糖有什么影响，有什么风险"
拆成：["饮酒对糖尿病患者血糖的影响",
       "糖尿病患者饮酒的健康风险",
       "糖尿病患者饮酒的注意事项"]
```

## 三、为什么要拆（Planning 的灵魂）

**因为检索是「按子问题分别去捞证据」的。** 下游 `retrieve_internal` 遍历每个子问题各自检索 top-k 再累积。

以例 1「二甲双胍的副作用和禁忌症」**若不拆**：拿整句去检索，向量检索可能主要召回「副作用」段落，「禁忌症」被挤掉 → 答案只讲副作用、禁忌缺失。拆开后两方面证据都进池，答案才完整。

> 一句话：**Planning 解决「单次检索覆盖不全」——复合问题拆成多方面，各自检索，证据更全面。**

## 四、关键设计点（面试考点）

1. **平行拆解（parallel decomposition）**：子问题互相独立、可同时检索。区别于「桥接/多跳型」（后跳依赖前跳答案）。
2. **结构化输出，不用正则**：`with_structured_output(SubQuestions, method="json_mode")` + Pydantic，强制返回合法 `{"questions": [...]}`，绝不用正则抠自由文本。
3. **故意不过度拆解**：prompt 明说单一问题只输出一个子问题。过度拆解会打散语义、引入噪声、白花检索。
4. **兜底（fallback）**：`subs = result.questions or [question]`，LLM 返回空时用原问题兜底，流程不断。
5. **衔接记忆**：拆的是 `standalone_question`（指代消解后的），不是原始 `question`，所以「那它的禁忌呢」已先被改成「二甲双胍的禁忌」再拆，子问题里不含悬空指代。

## 五、一个诚实的局限（讲出来加分）

**平行拆解搞不定「桥接型」问题。** 例：
```
"治疗高血压的一线药，它的副作用是什么"
```
要先查「一线药是谁」（如 ACEI），才能查「ACEI 的副作用」。平行拆会拆出悬空的「那个药的副作用」，检索全是噪声。

解决靠**链式精化**（先检索第一跳、把答案代入第二跳再检索），见 `docs/P2_5_DESIGN.md`；当前 `plan` 是平行版。面试被问「拆解有什么局限」，这是满分答案——能说出局限 + 知道怎么解。

## 六、面试问题清单（带答题要点）

1. 为什么要拆解问题，不拆直接检索不行吗？→ 单次检索覆盖不全；拆成多方面分别检索，证据更全。
2. 平行拆解 vs 多跳/桥接拆解，区别？你用哪种？→ 平行=子问题独立可并行；桥接=后跳依赖前跳。本项目平行；桥接需链式精化。
3. 拆解一定更好吗？→ 不一定，过度拆解打散语义、增噪，所以单一问题不拆。
4. 怎么保证 LLM 输出可解析？→ 结构化输出 + Pydantic，不用正则。
5. 为什么限制 1-3 个？→ 够覆盖医疗复合问题，又不过度拆、不爆检索量。
6. 拆解失败/返回空怎么办？→ `or [question]` 兜底原问题。
7. 多个子问题分别检索，证据会重复爆炸吗？→ `retrieve_internal` 用 `(source_id, chunk_id)` 去重，且每子问题只取 top-k。
8. 拆解用什么模型？能换吗？→ `_llm(config)`，按请求 flash/pro 动态选。
